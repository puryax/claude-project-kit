## 1. 開発環境と本番環境の違い（★ 最も見つけにくい ★）

### 1.1 Studio で再現しない不具合が必ずある
★★ **Studio は全部ローカルにあるので、通信・読み込み・ストリーミングが 0 秒。** ★★
本番では 0 秒ではない。**この差から出る不具合は、Studio では原理的に再現しない。**

**「深層」ではテスト計画を全項目パスして提出したあと、公開版で2件出た。**
→ **見た目や手触りを変えたら、本番でも一度は遊んで確かめること。**（D-239 / D-240）

### 1.2 `ReplicatedStorage` は参加した瞬間に全部クライアントへ送られる
`StreamingEnabled` の対象外なので、距離に関係なく丸ごと届く。
**サーバーしか使わないものを置くと、参加直後の通信が丸ごと無駄になる。**

「深層」の実測：`ReplicatedStorage` の中身 **7,741 個 → 47 個**にしたら、
参加直後の「ボタンを押しても 1〜2 秒反応しない」が消えた。（D-239）

★ **見分け方:** そのフォルダを `require` / 参照しているのがサーバーだけなら `ServerStorage` へ。★

### 1.3 `StreamingEnabled` のまま遠くへテレポートすると、何もない空間に落ちる
クライアントは**いま居る場所の周りしか持っていない。**
遠くへ飛ばすと、地形が流れてくるまで空中で待たされる（実測 10 秒前後）。

→ **飛ばす前に `Player:RequestStreamAroundAsync(位置, 秒数)` を呼ぶ。**（D-239）

### 1.4 「時間が経つと直る／入り直すと再現しない」＝ クライアントのキャッシュ
**素材がディスクに入りきったから直っただけ。**別の端末や新規プレイヤーでは再発する。
→ **直った、と判断しないこと。**

## 2. 通信と権限（サーバー／クライアント）

### 2.1 ★ 遅れるのは「サーバーとの往復が要る操作」だけ ★
不具合の切り分けで最も効く見方。

- **遅れない** … クライアントだけで完結する画面（手元のデータで開くUI）
- **遅れる** … サーバーへ送って返事を待つもの（攻撃・移動速度の変更・アイテム使用）

★ **人間の報告が「Aは遅いがBは遅くない」なら、この線で分かれていないか真っ先に疑う。** ★（D-239）

### 2.2 アニメーションは「再生の指示」だけが送られる
各クライアントが自分で再生している。**サーバーで直しても画面には反映されない。**（D-148）

そして★ **クライアントがその動きのデータを持っていなければ、そこから取りに行く。** ★
実測：**初回だけ画面が動き出すまで 1.0〜1.7 秒**かかる（2回目以降は 0.06〜0.09 秒）。
→ クライアント起動時に `ContentProvider:PreloadAsync` で先に取り寄せる。（D-238）

★ 渡すのは `Animation` の**インスタンス**。★ ID の文字列だけでは中身は落ちてこない。

### 2.3 ネットワーク所有権を持つ側が位置を決める
クライアントに所有権を渡した物体を**サーバーがテレポートしても付いてこない。**

「深層」では、体をワープさせたときにランタン（関節で吊った独立した物体）だけが取り残され、
**壁を突き抜けながら 1〜3 秒かけて手元まで飛んできた。**
→ **所有権を持っている側（＝クライアント）が置き直す。**（D-211 / D-240）

### 2.4 `_G` はサーバーとクライアントで共有されない
別のデータモデルなので、片方で書いても片方では読めない。

## 3. 見た目・物理

### 3.1 重なった平面はチラつく（Z-fighting）
床のタイルなどで、**天井面が同じ高さで重なると**移動に合わせてチラつく。
→ **交互に極小（0.02 スタッド程度）ずらす。**（D-230）

### 3.2 `PreRender` で関節（Motor6D）に書いても一切効かない
1フレームの順番は
**`PreRender` → 描画 → アニメーションが関節へ書く → `Stepped` → 関節の解決**。
`PreRender` で書いた値は**アニメーションに丸ごと上書きされる。**
→ **必ず `Stepped`（`PreSimulation`）で書く。**（D-165）

★ 効いているかは `Heartbeat` で読み直して確かめること。★

### 3.3 見た目を毎フレーム直す処理は、自分の書いた値に積み増して暴走する
「深層」では**縦のずれが 776 スタッドまで育った**（当たり判定は地面、見た目だけ天井の上）。
→ **必ず上限（クランプ）を付ける。**

### 3.4 実演から作ったモーションには「前進」が入っている
関節に入っているので、**当たり判定は動かず、見た目だけ進んで戻る。**
→ 見た目を消すのはクライアント、実際に体を動かすのはサーバー。**片方だけでは壊れる。**（D-148）

### 3.5 座ったまま CFrame でテレポートすると椅子を引きずる
→ 先に `Humanoid.Sit = false` にする。

### 3.6 Union（結合）は得も損もある
- **得**：同じ形が繰り返されるとき、描画が軽くなる
- **損**：★ **素材によってはテクスチャが消える** ★（「深層」の中層タイルで発生）
- **損**：結合すると**中身を1つずつ直せなくなる**
→ ★ **結合する前の元モデルを必ずどこかに残す。** ★（D-183 / D-185 / D-189）

## 4. 測り方（★ 間違えると存在しない不具合を追いかける ★）

### 4.1 `Sound.PlaybackLoudness` は編集モードでは動かない
編集モードで `Play()` しても `TimePosition` が進まず、値は 0 のまま。
→ **必ず Play（Client）で測る。**（D-237）

測り方：位置へ飛ばす → **0.15 秒待つ** → 8〜10 回読んで最大値を取る。
飛ばした直後は 0 が返るので、待ちが要る。

### 4.2 `AnimationTrack.Length` は読み込んだ直後は 0
後から届く（実測 0.43 秒）。**そこだけ見ると「問題なし」に見えてしまう。**
画面が本当に動いたかは、クライアントで `TimePosition > 0` を見る。
★ `IsPlaying` は指示が届いた時点で true になるので使えない。★（D-238）

### 4.3 レイキャストは「撃つ位置」で結果が変わる
「深層」では**壁の内側から撃っていた**ために、封鎖済みの開口部を
「10 個が未封鎖」と誤報した（実際は 0 個）。
→ **部屋の内側へ数スタッド入れてから撃つ。**（D-217 も同じ話：視線は相手側から撃つ）

### 4.4 前後・角度の判定は「部品の中心1点」ではなく「箱の形」で見る
中心だけで見ると、**大きい相手に密着したときに判定が裏返る。**（D-220）

### 4.5 UI の表示は合図に使えない
出しっぱなしのことがある。**状態そのものを見る**（「深層」では移動速度が 0 でいた時間で測った）。

### 4.6 ★ おかしいと思ったら、まず自分の測り方を疑う ★
「深層」で3回起きた。**確認スクリプトの側が間違っていた。**
実装を疑うのはその次。**順番を逆にすると、直さなくていいものを壊す。**（D-182 / D-186）

## 5. データと保存

### 5.1 読込に失敗したプレイヤーのデータは絶対に保存しない
初期データで上書きして**全資産が消える。**「読込失敗」と「新規プレイヤー」を区別すること。

### 5.2 穴の空いた配列は、保存すると辞書に化ける
DataStore は JSON に直すので `{ [2] = "x" }` は `{"2": "x"}` になって返ってくる。
→ **空きは nil ではなく空文字などで埋め、最初から詰めておく。**（D-82）

### 5.3 起動時の DataStore 502 は Roblox 側の障害のことがある
自分のコードを疑う前に、時間を置いて再確認する。（D-206）

### 5.4 ランキング（`OrderedDataStore`）は保存データとは別物
保存データ側を 0 にしても、**ランキングには古い記録が残り続ける。**
→ **両方消す。**（D-234 / D-236）

### 5.5 初期化は「項目を1つずつ 0 にする」のではなく、初期データを丸ごと敷き直す
1つずつだと必ず消し忘れる（「深層」では天井カウンタ・演出の既視フラグが残った）。
→ **新規が受け取るのと同じ中身を上書きする。**（D-236）

## 6. 入力・操作

### 6.1 数字キー 1〜9 は CoreGUI に取られている
`VirtualInput` は受け付けない。テストでは Remote を直接叩く。

### 6.2 判定は「キー」ではなく「入力そのもの」で行う
キーで分岐すると、タッチとコントローラーで必ず抜ける。（D-33）

### 6.3 走りながら操作すると、押した瞬間の位置がサーバーと食い違う
サーバー側の距離判定を、**表示する距離より少し広く**取る。（D-235）

## 7. 素材の受け入れ

### 7.1 人間が用意したモデルは、こちらの想定どおりの形をしていない
実際に起きたもの：**蓋が1部品ではなかった／入れ子の Model が入っていた／
グレーボックスの壁が透明だった／リグが R6 だった**。
→ **起動時に形を検査して、足りなければ警告を出してグレーボックスに落とす。**（D-59 / D-204 / D-205）

### 7.2 部品は名前で探さない
素材を差し替えると名前が変わる。**必ず付いている目印（Attachment やタグ）から辿る。**（D-240）

### 7.3 他人がアップロードした音源・アニメーションは、公開後に無音／無反応になることがある
配布設定が必要。**使えるかは `TimeLength` が 0 でないことで確かめる。**
プロパティの試聴では判断できない。（D-108）
