> **誰が読むか: まず人間。** 中の「最初のプロンプト」を Claude に貼る。
> ★ **Claude に「このファイルを読んで進めて」と渡してもよい。** ★ そのほうが速い。

**このファイルを新規セッションの Claude に読ませる。それだけで立ち上がる。**

---

## 人間がやること（5分）

1. プロジェクトのフォルダを作る
2. そのフォルダで Claude Code の新規セッションを立ち上げる
3. 下の「最初のプロンプト」をそのまま貼る

## ★ Claude がこの手順で必ず聞いてくること ★

以下は**人間が決めるべきこと**なので、答えを用意しておくと速い。

| 聞かれること | 例（「深層」の場合） |
|---|---|
| **このプロジェクトの核**（壊してはいけない一線） | 「持ち帰るまで宝は自分のものにならない、という葛藤」 |
| **期限** | 2026/09/15 |
| **全数値を集めるファイル** | `src/shared/Config.luau` |
| **絶対ルール5**（固有の一線） | 「怪物の速度がプレイヤーの走行速度 22 を超えてはならない」 |
| **絶対ルール7**（環境の検証手順） | 「一時ファイルを作って Studio に現れるか確かめ、必ず消す」 |
| **絶対ルール8**（測るとは何をすることか） | 「Play を開始して、実際の値を読む」 |

## 最初の1週間でやること

1. **`00_GDD.md` を書く**（何を作るのか。ここは Claude のチャット機能でやると速い）
2. **`01_SPEC.md` に数値を全部落とす**（曖昧なところは疑問として `05_DECISIONS.md` へ）
3. **`03_TASKS.md` にタスクと完了条件を並べる**（完了条件は**測れる形**で書く）
4. **環境構築**（Roblox なら `roblox/SETUP.md`）
5. **一番小さいタスクを1つ通してみる**（進め方が回るかの確認）

★ **5 が大事。** ★ いきなり大きいタスクから始めると、
進め方の欠陥に気づくのが遅れて、そのぶん全部やり直しになる。
