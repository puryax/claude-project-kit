# ②オリジナルのゲームを、構想ゼロから始める

> **誰が読むか: まず人間。** 作りたいものを思いついた日に、人間が開く。
> ★ **Claude に「このファイルを読んで進めて」と渡してもよい。** ★

**「作りたいものがまだ決まっていない」状態から始めるための手順。**
思いついたときにこのファイルを開けば、その日から動ける。

---

## 段階0〜1：構想を出して GDD を書く（Claude のチャット機能。3〜5時間）

★ **ここは Code ではなくチャットでやる。** ★ ファイルを作る段階ではないので。

★★ **チャットはローカルのファイルを読めない。** ★★
だから **`launch/FOR_CHAT.md` を1枚アップロードして「これを読んで進めて」と言う。**
構想の出し方・GDD の6項目・やってはいけないこと（推測・タスク表の作成）は、
**すべてそこに書いてある。**このファイルには繰り返さない（二重管理にしない）。

**人間がやること**
1. チャットを新規に開く
2. `FOR_CHAT.md` をアップロードし、「これを読んで、ゲームの構想から進めて」と言う
3. ★ **「核」と「やらないこと」が先に確定する**まで、他の話に進ませない ★
4. GDD が出力されたら、**自分で `00_GDD.md` として保存する**（チャットは書き込めない）

★ **チャットが「ここまでがチャットの担当です」と言ったら、そこで止める。** ★
続けさせると、境界を越えた成果物（タスク表・ファイル構成）が生まれて手戻りになる。
（2026-09-16 に実際に起きた。`FOR_CHAT.md` はその反省で作った）

### ★ 「深層」の GDD から学んだこと ★
- **「無限に潜れる」は最初の GDD に書いてあったが、有限化した**（D-01）
  → **GDD は絶対ではない。実装しながら削ってよい。**削った記録を残すこと
- **核を1行で書けたゲームは強い。**「持ち帰るまで宝は自分のものにならない」で
  最後まで判断がぶれなかった

## 段階2：環境を作る（Claude Code。30分）

`launch/START_NEW_PROJECT.md` の手順どおり。GDD を渡せば、そこから
`01_SPEC.md` と `03_TASKS.md` の下書きまで Claude が作れる。

## 段階3：一番小さいタスクを1つ通す（半日）

★ **いきなり大きいものから作らない。** ★
「プレイヤーが動いて、何か1つ拾える」くらいの最小の輪を先に通す。
ここで進め方の欠陥（同期・検証・認識合わせ）が全部あぶり出される。

---

## ★ 前作の資産をどこまで持ち込めるか ★

**コードはほぼ持ち込めない**（「深層」固有の作りなので）。
**持ち込めるのは考え方と落とし穴の知識**で、それが `ClaudeKit` の中身そのもの。

例外として、次は移植する価値がある：
- **テスト用コマンドの受け口**（`BindableFunction` を `ServerStorage` に立てる形。D-97）
- **素材ライブラリの考え方**（あれば Clone、無ければグレーボックス。D-59）
- **全数値を1ファイルに集める形**
