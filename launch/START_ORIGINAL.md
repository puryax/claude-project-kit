# ②オリジナルのゲームを、構想ゼロから始める

**「作りたいものがまだ決まっていない」状態から始めるための手順。**
思いついたときにこのファイルを開けば、その日から動ける。

---

## 段階0：構想を出す（Claude のチャット機能。1〜2時間）

★ **ここは Code ではなくチャットでやる。** ★ ファイルを作る段階ではないので。

```
ゲームの構想を一緒に固めたいです。まだ何も決まっていません。

私について:
- Roblox で1本、ソロ探索ゲームを完成させて公開した経験があります
- 作れるもの: 自動生成ダンジョン、敵AI、UI、DataStore、ランキング、課金
- 使える時間: 週30時間ほど
- 開発は Claude Code と Roblox Studio MCP で行います

次の順で聞いてください。一度に全部聞かず、1つずつ。

1. 私がどんなゲームを「遊びたい」のか（作りたい、ではなく）
2. 前作で「もっとこうしたかった」ことは何か
3. 前作と何を変えたいか（同ジャンルの改良か、別ジャンルか）
4. 上の答えから、企画案を3つ出してください
```

★ **3つ出させて、1つ選ぶ。** ★ 1案だけ出させると、良し悪しが判断できない。

---

## 段階1：GDD を書く（チャット。2〜3時間）

選んだ案について、`00_GDD.md` を書く。**必ず入れる項目：**

| 項目 | なぜ要るか |
|---|---|
| **このゲームの核**（1〜2行） | ★ ここが `CLAUDE.md` の「壊してはいけない一線」になる ★ |
| コアループ（1周の流れ） | タスク分割の骨格になる |
| 勝ち／負けの条件 | 仕様の曖昧さが最初に出る場所 |
| プレイヤーが選ばされること | ここが無いゲームは作っても面白くならない |
| 数値の当たり（HP・速度・時間） | あとで `01_SPEC.md` に落とす |
| **やらないこと** | ★ これが一番効く。書かないと際限なく広がる ★ |

### ★ 「深層」の GDD から学んだこと ★
- **「無限に潜れる」は最初の GDD に書いてあったが、有限化した**（D-01）
  → **GDD は絶対ではない。実装しながら削ってよい。**削った記録を残すこと
- **核を1行で書けたゲームは強い。**「持ち帰るまで宝は自分のものにならない」で
  最後まで判断がぶれなかった

---

## 段階2：環境を作る（Claude Code。30分）

`launch/START_NEW_PROJECT.md` の手順どおり。GDD を渡せば、そこから
`01_SPEC.md` と `03_TASKS.md` の下書きまで Claude が作れる。

---

## 段階3：一番小さいタスクを1つ通す（半日）

★ **いきなり大きいものから作らない。** ★
「プレイヤーが動いて、何か1つ拾える」くらいの最小の輪を先に通す。
ここで進め方の欠陥（同期・検証・認識合わせ）が全部あぶり出される。

---

## ★ 前作の資産をどこまで持ち込めるか ★

**コードはほぼ持ち込めない**（「深層」固有の作りなので）。
**持ち込めるのは考え方と落とし穴の知識**で、それが `ClaudeKit` の中身そのもの。

例外として、次は移植する価値がある：
- **テスト用コマンドの受け口**（`BindableFunction` を `ServerStorage` に立てる形。D-97）
- **素材ライブラリの考え方**（あれば Clone、無ければグレーボックス。D-59）
- **全数値を1ファイルに集める形**
