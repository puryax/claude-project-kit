## 立ち上げの手順

### 1. 人間に聞く（★ 勝手に決めない ★）

| 聞くこと | なぜ要るか |
|---|---|
| **このプロジェクトの核**（1〜2行） | `CLAUDE.md` の「壊してはいけない一線」になる |
| 何を作るのか／期限 | タスク分割の前提 |
| **全数値を集めるファイル**をどこにするか | 絶対ルール1になる |
| **固有の一線**（絶対ルール5） | 検証できる形で書けるものを1つ |
| **環境の検証手順**（絶対ルール7） | この環境で「同期が生きている」をどう確かめるか |
| **「測る」とは何をすることか**（絶対ルール8） | 「できたはず」を禁じるための具体手順 |

★ 一度に全部聞かず、1つずつ。★

### 2. `CLAUDE.md` を作る
`ClaudeKit\core\CLAUDE_TEMPLATE.md` が雛形。
★ **絶対ルール 7 と 8 は、この環境で実際に検証できる手順に書き換えること。** ★
雛形のまま貼ると意味を失う。

### 3. `docs/` を作る
`ClaudeKit\core\docs_template\` の 00〜06 をコピーして、分かっている範囲で埋める。

### 4. 最初の1週間の並びを提案する
GDD → 仕様の数値 → タスクと完了条件 → 環境構築 → **一番小さいタスクを1つ通す**

★ **最後の「一番小さいタスクを1つ通す」を必ず入れる。** ★
進め方の欠陥は、そこで初めて見つかる。

## このあと守ること（プロジェクト中ずっと）

- ★ **タスク着手前に、認識合わせのレベル（A/B/C）を人間に聞く** ★
- ★ **不具合は勝手に直さず、都度報告して判断を仰ぐ** ★
- ★ **「できたはず」で報告しない。動かして数字で測ってから報告する** ★
- ★ **おかしいと思ったら、まず自分の測り方を疑う。実装を疑うのはその次** ★
- セッション終了時に `docs/04_PROGRESS.md` の申し送りを更新する
- ★★ **「他のプロジェクトでも起きる」と分かったことは、その場で ClaudeKit へ書き戻してコミットする** ★★
